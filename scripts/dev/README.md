# scripts/dev — the real-browser proof for a UI drain

`node scripts/dev/browser-proof.mjs [--before <git-ref>] [--out <dir>]` mounts the **real** `RhythmEditView` (`src/rhythm-edit-view.ts`, bundled with esbuild and a tiny Obsidian shim in `browser/`) in a page that carries **Obsidian's own `app.css`** (read out of the installed app's asar by `asar-cat.mjs`) and the plugin's `styles.css`, with the real Rhythm Box widget in its sandboxed iframe, the real music edition (Verovio) and, behind a local `/compute` route, the real engine (the bundled Pyodide engine, in Node). `measure.ts` drives it through `cdp.mjs` (headless Chrome over the DevTools protocol): real pointer clicks inside the widget iframe, a sampler for flicker and layout jumps, geometry of the pane, screenshots, timings, and the engine's round trips. With `--before <ref>` it builds the same harness from that commit and compares a vault *without* the profile against it — `normalIdenticalToBefore` in `measurements.json` is "no harm to other vaults" in a browser. It is **not Obsidian** (Electron fonts, CodeMirror's block layout, Obsidian's workspace and Pyodide-in-Obsidian are not exercised); say so in the FEEDBACK.

**Wall-clock only.** Every number it reports is a real `performance.now()` in a real Chrome. Virtual time is banned here: nothing uses `Emulation.setVirtualTimePolicy` or fake timers, because a proof about debounce, flicker and engraving latency that runs on a fake clock proves nothing. To adapt it to another surface, copy `browser/entry.ts` (what is mounted), add the new scenario to `measure.ts`, and keep the three rules: the real class, real events, Obsidian's real CSS. Needs Google Chrome (or `CHROME=<binary>`), Obsidian installed, and the music wheels.

## The mutation runner (drain 2026-10-26-1300)

`node scripts/dev/mutate.mjs` replaces the one-at-a-time, edit-the-working-tree mutation scripts. It is tooling only (no product behaviour); its own tests are `scripts/mutate-runner.test.mjs` (they run in `npm test`).

```
node scripts/dev/mutate.mjs --diff HEAD~1                        # mutants of the lines the last commit changed
node scripts/dev/mutate.mjs --hand mutants.json --no-fail        # hand-written mutants (the semantic ones)
node scripts/dev/mutate.mjs --diff HEAD~1 --hand m.json --equivalent eq.json --out result.json
node scripts/dev/mutate.mjs --diff HEAD~1 --list                 # what it would run; runs nothing
```

- **The working tree is never written.** Each mutant is a file in its OWN scratch copy (`src`, `scripts`, `test`, `docs` and the small assets are copied, cloned on APFS; `node_modules`, `main.js`, `assets/wheels`, `assets/pyodide` are symlinked; the sibling repos some tests read through `../` are symlinked beside it; a small `.git` answers `git ls-files`/`git log` like the real one through `objects/info/alternates`). There is nothing to restore. The report ends with `working tree: unchanged (git status and N file hashes identical before and after)`, checked on every run (`--no-verify-tree` skips it); a change there is exit 3 and a bug in the tool.
- **Only the tests that can see the file run.** A map from source file to test files is built once (TypeScript compiler API for the import graph, plus every file NAME a file's text mentions: an `fs.readFileSync('music-edition.full.ts')` in a pin test is a dependency a pure import graph cannot see; a comment that names a file is a harmless extra edge) and cached in the system temp dir under a hash of all sources. A mutant in `X.ts` runs the test files that reach `X.ts` transitively. A test that boots Pyodide or bundles the real plugin ("engine" in the code, "slow" in the sense of tens of seconds) runs only when it NAMES `X.ts` itself or `X.ts` is the engine glue (`--glue`, default `pyodide-host`, `phrase-engine`, the engine bundle). A mutant whose file no test reaches is reported as `NO TEST`: a gap by itself, and a failure. Tests that import `scripts/dev/cdp.mjs` (a Chrome study) are never run; they are listed. A test file that merely quotes real file names in its fixtures (like the tool's own) starts with the comment `// mutate-map: imports only`. When such a test also NAMES a mutated file without importing it (a CLI test that runs the file: the tool's own is the example) the report carries a `note:` line saying so, because that test is then not in the pool and the file's CLI wiring is covered by nothing in the run: list the test in the `tests` field of a `--hand` mutant (or pass `--glue`).
- **A mutant dies at its first failing test.** Each test file runs in its own `node --test` process, a few at a time (`--test-concurrency`), in the order of the likeliest, cheapest kill (tests that name the file first, light before engine, cheapest first by durations measured on earlier runs); the first failing file ends the mutant and kills the files still running. Only a survivor runs everything. Several mutants run at once (`--jobs`, default half the cores, at most 8; `--engine-jobs` of them may be running engine tests).
- **A hang is a kill, a slow run is not.** A mutant that does not finish in `--timeout` seconds (default 90) is killed whole (its process group) and counted as killed by timeout, reported as such. Because a survivor that is merely slow under load looks exactly like a hang, every timeout is run again ALONE at the end; only a mutant that times out in the quiet keeps the label.
- **Diff-seeded mutants.** `--diff <ref>` reads `git diff -U0 <ref> -- src scripts` and mutates only the lines that changed, in source files (not tests, not `*.generated.ts`, not `test-support`, not `scripts/dev`), by the TypeScript AST so types, module specifiers and a `super()` call are never touched: `===`/`!==`, `==`/`!=`, `<`/`<=`, `>`/`>=`, `&&`/`||`, `+`/`-`, a number to `n+1`, `true`/`false`, drop a `!`, a string to `''`, an `if` condition to `false` and to `true`, `return x;` to `return;`, a statement dropped. Ids are stable (`file:line:op#k`); `--max N` takes an even stride. **Hand-written mutants** (`--hand`) have today's shape, `[file, name, from, to, tests?]` (or objects), and `from` must occur exactly once (else `n/a`, said out loud); `--map-only` ignores the `tests` a row lists and uses the map.
- **The loop cap** (`--max-loop`, default 5,000,000; 0 = off). A mutant that removes a loop's exit used to hang until `--timeout` (90 s; the 0820 run had three). In the MUTATED copy of the file, every unbounded loop header (`while (true)`, `for (;;)`, `for (init; ; update)`) now counts its iterations per site and throws `forge-mutate: loop cap exceeded at L<line>` after the cap: the mutant dies in a fraction of a second and the report counts it as `by loop cap`, apart from the timeouts. The helper is appended after the code (no line moves); a loop whose header the rewrite cannot read (a call in the init, say) is left to the timeout; the real tree is never rewritten. A mutant killed by the cap still goes through the baseline-after check like every kill.
- **The report** says generated, killed (by timeout), survived, uncovered, equivalent-explained, invalid, not applicable, not run, the wall time, and prints every survivor as `file:line [id]  "original" -> "mutated"`. `--equivalent eq.json` is the hand-annotated list, `{ "<id or name>": "why it cannot be observed" }`: those survivors print as `equivalent` with the reason and no longer fail the run. `invalid` is a mutant that is not valid code (the files never loaded); `not run` is a survivor that proves nothing (everything the mutant was asked to run was skipped). Exit 0 nothing unexplained survived (or `--no-fail`), 1 an unexplained survivor / a gap / a not-run, 2 usage or an untrustworthy baseline, 3 the working tree changed.
- **The baseline.** By default the test files that KILLED something are run once on the UNMUTATED tree after the mutants (`--baseline after`: a handful of files, seconds): a kill by a test that fails anyway proves nothing, so the run exits 2 — but the FULL REPORT is still printed (a 20-60 minute run is never thrown away), headed by `BASELINE NOT GREEN: kills by these files are unproven: <files>` (drain 2026-10-27-0710). A file is only named red when it fails ALONE: every file that failed in the batch is re-run by itself first, and one that passes alone is reported as load (`failed in the batch but pass alone`), not as a red baseline. `--baseline first` runs the whole pool unmutated before any mutant instead (slower, and the way to see a red suite before spending the time).
- **`0 tests in the pool for <file>` and `--glue`.** A mutant in a file no test in the pool can see is reported as `NO TEST  <file>:<line> [id]  0 tests in the pool for <file>: add \`--glue\` or name the file in a test` (also on the progress line), never as a bare `uncovered`. The usual cause is the engine-booting rule above: a test that boots the real engine/plugin runs for a file only when it NAMES the file (an import or a file it reads) or the file matches `--glue`. **Which files need `--glue`:** any file the real-plugin wiring tests cover without naming it — `src/score-first.ts`, `src/main.ts`, `src/server.ts`, `src/phrase-view.ts` and the new notebook / sentence wiring (`notebook-*`, `sentence-plan-*` glue) — e.g. `--glue '(score-first|main|server|phrase-view|notebook|sentence-plan|pyodide-host|phrase-engine|real-rhythm-engine|engine-bundle)\.|^assets/engine/'`. `--glue` REPLACES the default (`(pyodide-host|phrase-engine|real-rhythm-engine|engine-bundle)\.|^assets/engine/`), so repeat its alternatives. Without it, 65 `score-first.ts` survivors in drain 1000 were artifacts of the test map, not gaps in the tests.
- **Never run `--file` on `scripts/dev/reaper.mjs`.** Mutants of a self-reaping tool leave orphan sidecars (43 spinning processes once); hand mutants only, one at a time, with `--timeout`.
- **Measured** (2026-10-26, 18 cores): Iteration 131's 31 hand-written mutants in 1m45s (the same 6 survivors, 25 kills as recorded; the one-at-a-time script took 4 to 11 minutes), Iteration 130's 52 on a checkout of `017ff70` (51 kills, the one recorded survivor). The floor of a pass is its slowest survivor: a survivor must run every test that can see its file.

## No orphans (2026-10-27-0715)
Measured, not assumed: a mutation runner killed with `-9` (or whose terminal closed) left its `node --test` group running with ppid 1, and a hung mutant spun at 100% CPU for ever; a `cdp.mjs` script killed the same way left a whole headless Chrome (11 processes) and its profile; an interrupted `drain-matrix.sh` left 8 registered git worktrees (Ctrl-C) or 21 of 65 processes running (SIGTERM to the script alone).
- `scripts/dev/reaper.mjs`: a sidecar the runner and `cdp.mjs` start in their own session with a pipe on its stdin; when the parent dies for ANY reason (SIGKILL included) it kills every process group the parent registered and removes the paths it registered. `FORGE_REAPER=off` disables it (the tests' control runs).
- The runner, `cdp.mjs` and the matrix also handle SIGINT / SIGTERM / SIGHUP and clean up; test children get `NODE_OPTIONS=--max-old-space-size=1024` (was 2048 until 2026-10-31-1125; `FORGE_TEST_HEAP_MB` overrides; a cap already set wins).
- `bash scripts/dev/reap.sh [--dry-run] [--quiet]`: the by-hand broom (the matrix and the runner call it quietly at start and end only when `FORGE_REAP=1`: it sweeps shared temp space by name, so it is never automatic). It touches only orphans (ppid 1, yours, older than a minute, matching a test runner or cdp's headless Chrome) and stale `drain-matrix.*` / `forge-mutate-*` / `cdp-*` directories in `$TMPDIR`; never a process with a living parent.

## A memory budget, one heavy thing at a time (2026-10-31-1125)

Why: on 2026-10-31 the 24 GB driver machine kernel-panicked three times (08:58, 20:35, 20:58: `watchdog timeout: no checkins from watchdogd`, about 914 free pages, swap disabled). The 20:58 one was a mutation pass at the old defaults (8 mutants at once x 2 test files x a 2 GB heap). Measured afterwards: a *runaway* mutant (one that removes a non-literal loop exit) grows a test process to 3.7 GB and beyond under a 1 GB `--max-old-space-size` - the V8 heap cap does not bound it - so a few of them at once exhaust the machine.

What the tools do now (all in `mem-core.mjs`, pure and tested; `mem-plan.mjs` prints what the numbers allow on this machine):

- **`FORGE_MEM_BUDGET_MB`** (default: half the RAM, but no more than what the machine can really give back right now less 1 GB, and at least 2048 - on the driver's 24 GB machine with its apps open that is about 4 GB, not 12). The mutation runner caps `--jobs` x test-concurrency so that (test processes x what one may cost) fits it, and says so on stderr when it lowers a flag (`--jobs 8 -> 6, test concurrency 2 -> 1`); a flag does not defeat the budget, the variable raises it. What one test process may cost = `max(heap cap, RSS cap)`.
- **Heap cap `FORGE_TEST_HEAP_MB`** (default 1024) and **RSS watchdog `FORGE_TEST_RSS_MB`** (default 1.5 x the heap cap): four times a second the runner reads the resident memory of every live test process *tree*; one over the cap is killed at once and its mutant is reported as `killed ... by heap cap` (never as a survivor, and not left to the 90 s timeout).
- **A cap per test file, learned (drain 2026-11-02-1151).** The cap is one number, but a test file is not: a real-plugin test (it bundles the plugin, esbuild and node, the resident memory of the whole tree summed, about 2 GB) is over 1.5 GB WITHOUT any mutant, so the old runner killed it at once, called its baseline red and every kill by it unproven (`BASELINE NOT GREEN` for `src/phrase-registration.test.ts`, which passes in the real tree: drains 1135 and 1149; the scratch copy was never the difference). Now a file killed by the cap is MEASURED once, alone and unmutated, under a high ceiling (4 x the cap, at least 4 GB); its cap for this run becomes what it needs times 1.5 and the runner says so (`mutate: <file> needs about N MB of process tree unmutated (the cap is C MB, FORGE_TEST_RSS_MB): its cap is raised to R MB for this run`); the mutants it was killed in under the old cap are run again under the new one. A mutant that really runs away is still killed by the cap (still `by heap cap`). An explicit `FORGE_TEST_RSS_MB` stays the default for every other file. When a baseline IS red, the report names the test and the failing line (`<file>: test "<name>" failed: <error> (<file>:<line>)`), not only the file.
- **The time box `--time-box <minutes>`** (drain 2026-11-02-1154, card section 22: a pass is at most 15 minutes): a mutant not STARTED when the minutes, counted from the start of the run, are over is reported as `not run` (`NOT RUN ... the time box (--time-box) was over before it started`) and counts toward the unexplained exit status like any not-run; a mutant already running finishes (within `--timeout`) and is judged as usual. No flag, no limit.
- **The pause gate**: before it starts a test process the runner reads the free memory (`vm_stat` free + speculative + purgeable + half the file-backed pages, and `memory_pressure -Q`; NOT `os.freemem()` and NOT free + inactive: with swap off, inactive anonymous memory can only be compressed, never given back - on 2026-11-02 that sum said 6.4 GB 'available' while the machine was killing the desktop apps). Below `max(1536 MB, 1.5 x heap)` available or under 8 % free it PAUSES - `mem-gate: paused, N MB available ...` on stderr - and resumes by itself (`mem-gate: resumed after N s`); after 10 minutes it goes on and says so. `FORGE_MEM_READ_FILE=<json>` replaces the reading (the tests' fake low-memory machine).
- **The matrix** runs its legs' `npm test` with `--test-concurrency=<n>` (`FILE_CONC`, from `mem-plan.mjs matrix-files`): the files one leg runs at once are capped so that files x `FORGE_MATRIX_FILE_MB` (default 600, measured: 8.3 GB of RSS for 16 files at once) x legs fits the budget (node's own default is every core minus one per leg: 34 files at once, 11.5 GB of tooling). The nested-matrix tests already use stub legs.
- **`heavy-lock.mjs`**: the matrix, the mutation runner and the real-Chrome measures (`cdp.mjs openPage`) take `$TMPDIR/forge-heavy.lock` (pid, start time, label inside) before they start. A second heavy run WAITS and says who holds it (`heavy-lock: waiting - drain-matrix (pid ..., running N s) holds ...`). Stale-aware: a holder (and the run it started) that is gone, or whose pid now belongs to another process, is taken over (`taking over a STALE lock`) - a `kill -9` never leaves the machine locked. `bash scripts/dev/reap.sh` clears a stale lock and never a live one; `node scripts/dev/heavy-lock.mjs status`; `FORGE_HEAVY_LOCK=off` turns it off; `FORGE_HEAVY_LOCK_WAIT_MS` bounds the wait (default 3 h). Not taken inside a test run (`NODE_TEST_CONTEXT`), and not by a tool a lock holder started (`FORGE_HEAVY_LOCK_HELD`).
- **`mem-watch.mjs`** is the sampler that produced the numbers: `node scripts/dev/mem-watch.mjs --out <csv> [--guard-free-mb N] -- <command>`; every 2 s it sums `ps` resident memory by family (runner children, matrix legs, Chrome, pytest, Obsidian, Claude), appends a CSV line, and prints each family's peak and the minute it happened. Write the CSV somewhere that survives a reboot (not `/tmp`: the 20:58 panic took its evidence with it). A guard on a 2 s sampler cannot pre-empt a stall; the budget and the watchdog are what prevent one.
- RSS sums overstate (shared and compressed pages): a pass whose runner family summed to 18.7 GB never took the machine's available memory below 7.4 GB. Read both columns.
