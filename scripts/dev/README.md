# scripts/dev — the real-browser proof for a UI drain

`node scripts/dev/browser-proof.mjs [--before <git-ref>] [--out <dir>]` mounts the **real** `RhythmEditView` (`src/rhythm-edit-view.ts`, bundled with esbuild and a tiny Obsidian shim in `browser/`) in a page that carries **Obsidian's own `app.css`** (read out of the installed app's asar by `asar-cat.mjs`) and the plugin's `styles.css`, with the real Rhythm Box widget in its sandboxed iframe, the real music edition (Verovio) and, behind a local `/compute` route, the real engine (the bundled Pyodide engine, in Node). `measure.ts` drives it through `cdp.mjs` (headless Chrome over the DevTools protocol): real pointer clicks inside the widget iframe, a sampler for flicker and layout jumps, geometry of the pane, screenshots, timings, and the engine's round trips. With `--before <ref>` it builds the same harness from that commit and compares a vault *without* the profile against it — `normalIdenticalToBefore` in `measurements.json` is "no harm to other vaults" in a browser. It is **not Obsidian** (Electron fonts, CodeMirror's block layout, Obsidian's workspace and Pyodide-in-Obsidian are not exercised); say so in the FEEDBACK.

**Wall-clock only.** Every number it reports is a real `performance.now()` in a real Chrome. Virtual time is banned here: nothing uses `Emulation.setVirtualTimePolicy` or fake timers, because a proof about debounce, flicker and engraving latency that runs on a fake clock proves nothing. To adapt it to another surface, copy `browser/entry.ts` (what is mounted), add the new scenario to `measure.ts`, and keep the three rules: the real class, real events, Obsidian's real CSS. Needs Google Chrome (or `CHROME=<binary>`), Obsidian installed, and the music wheels.

**Phrases (M5, drain 2026-10-22-1850).** `measure-phrase.ts` is the same recipe for the phrase tab: the real `mountPhrase` (control strip + live Score), the real music edition, the real engine behind `/phrase`. Build `OUT=<dir>/harness-phrase.js EDITION=music ENTRY=entry-phrase.ts node scripts/dev/browser/build.mjs`, put `app.css` and `plugin-styles.css` in `<dir>` (browser-proof.mjs makes them), then `node scripts/dev/measure-phrase.ts <dir>`. It exits non-zero unless: 8 bars engraved, a tempo mark per bar and part, the `<midi-player>`'s note sequence has a tempo change at every bar start (within 5 ms), Verovio's timeMap puts the bar starts in the same places, a control edit writes the JSON and redraws, a source-bar edit redraws, and the console has no errors. Audio is not played (headless): it measures what the player is given to schedule.

**Pinning a bar (drain 2026-10-24-1100).** `measure-pin.ts` sweeps a grid of points over a phrase tab's and a mix tab's engraving, classifies what the browser says is under each point (notehead, stem, beam, staff line, rest, label, empty), and clicks a few points of every kind in every bar with REAL DevTools pointer events (a move, then press and release at once): first, repeated, and after another bar is pinned; what pinned is read from the DOM. Build `OUT=<dir>/harness-phrase.js EDITION=music ENTRY=entry-phrase.ts node scripts/dev/browser/build.mjs` (with `app.css` and `plugin-styles.css` beside it), then `node scripts/dev/measure-pin.ts <dir>`. It also answers the Ghost question (noteheads with nothing pinned vs pinned, same weight). Exit 1 when a verdict is false.

## The mutation runner (drain 2026-10-26-1300)

`node scripts/dev/mutate.mjs` replaces the one-at-a-time, edit-the-working-tree mutation scripts. It is tooling only (no product behaviour); its own tests are `scripts/mutate-runner.test.mjs` (they run in `npm test`).

```
node scripts/dev/mutate.mjs --diff HEAD~1                        # mutants of the lines the last commit changed
node scripts/dev/mutate.mjs --hand mutants.json --no-fail        # hand-written mutants (the semantic ones)
node scripts/dev/mutate.mjs --diff HEAD~1 --hand m.json --equivalent eq.json --out result.json
node scripts/dev/mutate.mjs --diff HEAD~1 --list                 # what it would run; runs nothing
```

- **The working tree is never written.** Each mutant is a file in its OWN scratch copy (`src`, `scripts`, `test`, `docs` and the small assets are copied, cloned on APFS; `node_modules`, `main.js`, `assets/wheels`, `assets/pyodide` are symlinked; the sibling repos some tests read through `../` are symlinked beside it; a small `.git` answers `git ls-files`/`git log` like the real one through `objects/info/alternates`). There is nothing to restore. The report ends with `working tree: unchanged (git status and N file hashes identical before and after)`, checked on every run (`--no-verify-tree` skips it); a change there is exit 3 and a bug in the tool.
- **Only the tests that can see the file run.** A map from source file to test files is built once (TypeScript compiler API for the import graph, plus every file NAME a file's text mentions: an `fs.readFileSync('music-edition.full.ts')` in a pin test is a dependency a pure import graph cannot see; a comment that names a file is a harmless extra edge) and cached in the system temp dir under a hash of all sources. A mutant in `X.ts` runs the test files that reach `X.ts` transitively. A test that boots Pyodide or bundles the real plugin ("engine" in the code, "slow" in the sense of tens of seconds) runs only when it NAMES `X.ts` itself or `X.ts` is the engine glue (`--glue`, default `pyodide-host`, `phrase-engine`, the engine bundle). A mutant whose file no test reaches is reported as `NO TEST`: a gap by itself, and a failure. Tests that import `scripts/dev/cdp.mjs` (a Chrome study) are never run; they are listed. A test file that merely quotes real file names in its fixtures (like the tool's own) starts with the comment `// mutate-map: imports only`.
- **A mutant dies at its first failing test.** Each test file runs in its own `node --test` process, a few at a time (`--test-concurrency`), in the order of the likeliest, cheapest kill (tests that name the file first, light before engine, cheapest first by durations measured on earlier runs); the first failing file ends the mutant and kills the files still running. Only a survivor runs everything. Several mutants run at once (`--jobs`, default half the cores, at most 8; `--engine-jobs` of them may be running engine tests).
- **A hang is a kill, a slow run is not.** A mutant that does not finish in `--timeout` seconds (default 90) is killed whole (its process group) and counted as killed by timeout, reported as such. Because a survivor that is merely slow under load looks exactly like a hang, every timeout is run again ALONE at the end; only a mutant that times out in the quiet keeps the label.
- **Diff-seeded mutants.** `--diff <ref>` reads `git diff -U0 <ref> -- src scripts` and mutates only the lines that changed, in source files (not tests, not `*.generated.ts`, not `test-support`, not `scripts/dev`), by the TypeScript AST so types, module specifiers and a `super()` call are never touched: `===`/`!==`, `==`/`!=`, `<`/`<=`, `>`/`>=`, `&&`/`||`, `+`/`-`, a number to `n+1`, `true`/`false`, drop a `!`, a string to `''`, an `if` condition to `false` and to `true`, `return x;` to `return;`, a statement dropped. Ids are stable (`file:line:op#k`); `--max N` takes an even stride. **Hand-written mutants** (`--hand`) have today's shape, `[file, name, from, to, tests?]` (or objects), and `from` must occur exactly once (else `n/a`, said out loud); `--map-only` ignores the `tests` a row lists and uses the map.
- **The report** says generated, killed (by timeout), survived, uncovered, equivalent-explained, invalid, not applicable, not run, the wall time, and prints every survivor as `file:line [id]  "original" -> "mutated"`. `--equivalent eq.json` is the hand-annotated list, `{ "<id or name>": "why it cannot be observed" }`: those survivors print as `equivalent` with the reason and no longer fail the run. `invalid` is a mutant that is not valid code (the files never loaded); `not run` is a survivor that proves nothing (everything the mutant was asked to run was skipped). Exit 0 nothing unexplained survived (or `--no-fail`), 1 an unexplained survivor / a gap / a not-run, 2 usage or an untrustworthy baseline, 3 the working tree changed.
- **The baseline.** By default the test files that KILLED something are run once on the UNMUTATED tree after the mutants (`--baseline after`: a handful of files, seconds): a kill by a test that fails anyway proves nothing, and the run is refused (exit 2, the failing names printed). `--baseline first` runs the whole pool unmutated before any mutant instead (slower, and the way to see a red suite before spending the time).
- **Measured** (2026-10-26, 18 cores): Iteration 131's 31 hand-written mutants in 1m45s (the same 6 survivors, 25 kills as recorded; the one-at-a-time script took 4 to 11 minutes), Iteration 130's 52 on a checkout of `017ff70` (51 kills, the one recorded survivor). The floor of a pass is its slowest survivor: a survivor must run every test that can see its file.
